# Облачный сборщик видеоряда (бесплатно, на серверах GitHub)

Собирает новостной видеоряд **на второй канал** на чужих машинах — не на твоём
компьютере и не на этом. Без медиатеки (её там нет, всё из поиска).

**Смысл:** самое долгое в подготовке дашборда — поиск картинок (Яндекс/
Wikimedia режут по одному IP, ~40 мин на 100+ сцен). В облаке поиск идёт
**на ~15 машинах одновременно**, у каждой свой IP — баны обходятся, ~2 мин.

**ПРАВИЛА (Андрей, 2026-09-06, «всё чётко»):**
1. Весь поиск (осн. сцены + всплывашки) и вся сборка — в GitHub. Локально —
   ТОЛЬКО медиатека (быстро, диск).
2. **Облако СТОП на дашборде.** Видео до «собирай» не собирается — HARD GATE.
   Первый прогон: fetch → merge → дашборд → стоп. Сборка (clips/concat/sfx) —
   отдельный триггер после утверждения.  ⚠️ TODO: сейчас workflow гонит всё
   одним прогоном — переделать.
3. Дашборд отдаётся сразу после поиска, не после рендера.
4. Готовый видеоряд кладётся в исходную папку SRT на D:.  ⚠️ TODO.
5. Всплывашки шардить в матрицу (сейчас серийно в assemble).  ⚠️ TODO.

**Облако — не единственная точка отказа.** Любой затык (бан, ошибка, просто
долго) → `run.sh` сам печатает большими буквами «переходим на локалку» и
запускает обычную локальную сборку по старым правилам.

---

## Как пользоваться — одна команда

```bash
~/.claude/skills/news-video/cloud/run.sh  ~/projects/<проект>  [имя]
```

Она сама: отправит проект → дождётся сборки → скачает результат в
`~/projects/<имя>-cloud/`. Если облако не справилось за 55 мин или упало —
переключится на локальную сборку и покажет локальный дашборд.

Дальше как всегда: открываешь дашборд, правишь сцены (🔎 / ⬆️ / всплывашки),
и на пересборку **тем же именем**:

```bash
~/.claude/skills/news-video/cloud/ship.sh  ~/projects/<имя>-cloud  <имя>
```

При пересборке облако переклеивает только изменённые сцены (~5 мин, не 15).

## Три режима (определяются сами)

| Что в проекте | Что делает облако |
|---|---|
| `<name>.scenes.json` уже классифицирован + `images/` с кадрами | только сборка твоего дашборда (0 расхода Max) |
| `<name>.scenes.json` классифицирован, кадров нет | параллельный поиск кадров → дашборд → сборка (0 расхода Max) |
| только `*-caption.srt` + озвучка | + Claude в облаке режет и классифицирует (нужен `/install-github-app`, ест Max) |

Обычный путь: сценарий на сцены раскладываю я в сессии (быстро), потом
`run.sh` — облако параллельно ищет кадры.

---

## Как это устроено (3 задания в одном прогоне)

1. **setup** — берёт проект из `queue/<name>/`, (если надо и есть токен)
   классифицирует, режет сцены на шарды по ~8.
2. **fetch** — матрица: по одному раннеру на шард, каждый на своём IP,
   качает свой кусок и отдаёт картинки артефактом.
3. **assemble** — сливает все шарды в одну `images/`, чинит совпадения
   (два раннера скачали одно фото на разные сцены), собирает
   клипы → всплывашки → склейка → звук, выкладывает немой mp4 + дашборд
   + QA-отчёт в GitHub Release с именем `<name>`.

## Флаг BUSY (приоритет живой сессии)

```bash
cloud/busy.sh on    # в начале работы в сессии
cloud/busy.sh off   # в конце
```

Пока стоит `BUSY`, запуски по push откладываются до ночного прогона
(01:00 UTC). Прогресс каждого шага в `queue/<name>/progress.json` —
отложенный проект продолжается с того же места.

## Логи — за облаком следим плотно

С каждым готовым роликом в Release приезжают:

| файл | что в нём |
|---|---|
| `QA-report.md` | **читать первым.** Сцены без кадра, кадры из веб-поиска (не CC), один файл на разных сценах, нарушен видео-лид, всплывашки без фото, длина не сходится, невыполненные шаги |
| `classify_report.md` | облачный Claude построчно: какой запрос на какую сцену и почему; где не уверен |
| `pipeline.log` | полный транскрипт: каждая команда + вывод (ffmpeg stderr тоже) |
| `report.json` | метрики по шагам |

Логи выкладываются даже если сборка упала (артефакт `cloud-logs-<name>`).

## Лимиты (всё бесплатно)

- GitHub Actions: приватный репо — 2000 минут/мес НА АККАУНТ. Реально
  измерено (2026-09-21, по job-таймингам): обычный ролик (~60 сцен, 5-6
  мин) ≈ 18-23 минуты биллинга; большой (130+ сцен, 14+ мин) ≈ 40-45 минут.
  При темпе ~8-10 роликов/день один аккаунт хватает на ~12 дней — поэтому
  4 аккаунта в ротации (см. выше), а не один.
- Хранение: готовые ролики в Releases (git не раздувают), артефакты чистятся
  через 2 дня, `queue/<name>/` удаляется после сборки.
